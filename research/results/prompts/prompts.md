# Prompts sent to models

Generated by `scripts/paper_prompts.py` from the code (do not edit by hand); rendered for the paper in `paper/sections/app_prompts.tex` (App. app:prompts-full). Examples: development seed 600 (JevGym-Hard 7003).

This subsection lists every prompt our code sends to a model in the experiments, generated from the code by this script. Examples come from development seed 600, which no evaluation uses. ⟨name⟩ marks a value filled in at run time, an italic [note] marks our shortening, and a hook marks a line we wrapped. No prompt contains the label of the decision it asks about. The answer key and every label stay in the decision log. Training data and teacher labels add no prompt of their own, since teachers answer the same requests and training rows use the trained-model format.

## Decision-model inputs

Every decision model reads the same state text and one typed question, a choice among options or a yes/no question. The reference loop builds the state below. The questions come next, then the request that carries them.

### P3. Questions at tool calls

Source: `src/jevharness/harness/prompts.py`, `src/jevharness/harness/agent.py`, `src/jevharness/harness/tools.py`. Options carry the first line of each tool description. The decision model fills an argument only when its values are bounded, as with an enum or a boolean, or can be copied from the state. The copy options are the spans the code extracts. Free text always goes to the LLM.

```text

[Tool arguments: one question per argument]

Options: the 3 values copied from the state (Lena Wang, Lena, Wang), then
<OTHER: none of these / needs generation>

Options: the enum all, pending, shipped, delivered, cancelled

[Tool guard: yes/no]
```


## How each decision model reads a question

Jev, OpenJev and StartLux-Decision receive the request above and build their prompts inside their own servers [typesafe2026jev,openjev2026,startlux2026decision]. Every other decision model gets one of the prompts below, where ⟨state⟩ is the state text shown above.

### P6. Intern-Decision (one pass for all questions)

Source: `src/jevharness/decision/intern_decision.py: compile_row`. The vendor's prompt compiler, copied with its licence. The state is JSON-encoded. Each field's answer is read at its `<decision>` placeholder, so k questions cost one forward pass.

```text
[system]
You are a careful decision assistant. Use the state and decision schema in the user message to make the requested decisions. For every field, choose exactly one answer symbol (e.g. A, B, C, ...) from its listed options and return one valid JSON object mapping each field name to its chosen symbol. Use the field names and symbols exactly as given. Do not include explanations, Markdown, or extra text.
[user]
Return one answer for every field using the supplied answer symbols.

## State
"⟨state⟩"
## Decision schema
tool_select: Which tool should the agent call next?
    A = get_orders_archive: List a customer's orders from the archive of a past calendar year (orders older than 12 months only).
    B = set_reminder: Set a reminder.
    C = finish: Call when the task is complete. Provide the final answer (or a short summary).
stop: Has the task already been fully completed, so the agent should stop now?
    A = no: The answer is no (negative, or disagree with the claim).
    B = yes: The answer is yes (affirmative, or align with the claim).
[assistant]
{
    "tool_select": "<decision>",
    "stop": "<decision>"
}
```

```text
{"Q1": {"A": "<prob>", "B": "<prob>", "C": "<prob>"}, "Q2": {"yes": "<prob>", "no": "<prob>"}}

[last block in the label variant]
```

## The agent LLM on DecisionGym

The agent LLM sees a short system prompt, the task and the tool results, plus the notes below when a decision point acts on its turn.

### P14. Messages the harness adds to the LLM's context

Source: `src/jevharness/harness/prompts.py`, `src/jevharness/harness/agent.py`. The reflection reply and the stop-guard rejection stay in the context. They are appended to the last tool message when one precedes them, because Gemini 3 returns an empty reply after a user turn there. The other notes go with one call only. Tool assist adds no text and offers the LLM only the model's top tools and finish. Routing adds no text either. It sends the step to the cheaper LLM with the same messages.

```text
[Reflection: asked as a user turn, the reply kept]
Pause. In <=4 sentences: assess progress toward the task, identify any mistake so far, and state the best next step. Do not call tools.
[Reflection] ⟨the LLM's reply⟩

[Recalled memories, before the LLM's turn]
[Memory]
- [m⟨id⟩] ⟨memory text⟩
- [m⟨id⟩] ⟨memory text⟩

[Stop guard rejected a finish]
[Verifier] The task may not be complete yet, or the final answer may be wrong. Re-check the requests and recompute the answer before calling finish.
[Stop trigger fired: a forced finish call]
The task appears complete. Call finish with the final answer.

[Tool guard rejected the call]
[Verifier] Your proposed call `⟨tool⟩(⟨arguments⟩)` was judged likely wrong. Reconsider and choose the correct next tool call.
[Argument guard rejected one argument]
[Verifier] In your proposed call `⟨tool⟩(⟨arguments⟩)`, the value of the argument `⟨argument⟩` was judged likely wrong. Reconsider and choose the correct next tool call.

[Verification pass at tool choice: every tool offered]
[Check] Before your proposed call `⟨tool⟩(⟨arguments⟩)` runs, re-read the task and the observations so far and check that this is the right tool to call now. If it is, make the same call again; if not, make the right call instead.
[Verification pass at tool arguments: the call forced to the proposed tool]
[Check] Before your proposed call `⟨tool⟩(⟨arguments⟩)` runs, re-read the task and the observations so far and check every argument value. Call `⟨tool⟩` again, with the same arguments if they are right or with corrected arguments if not.

[Decision model chose the tool and the LLM fills the rest]

[Argument assist: the model's shortlists]
You must now call `⟨tool⟩`. Choose these arguments from the shortlists:
- `⟨argument⟩`: one of [⟨value⟩, ⟨value⟩]
```
